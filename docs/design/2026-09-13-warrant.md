# Warrant: a claim's support, computed from the tree

**Status:** proposed
**Issue:** [#126](https://github.com/zmainen/elife-claim-trees/issues/126)
**Frames:** [#20](https://github.com/zmainen/elife-claim-trees/issues/20) · [#28](https://github.com/zmainen/elife-claim-trees/issues/28) · [#36](https://github.com/zmainen/elife-claim-trees/issues/36) · [#31](https://github.com/zmainen/elife-claim-trees/issues/31)
**Depends on:** `docs/claim-format.md`, the `verification`, `prediction-outcome` and `stance` layers, `scripts/relations.py`, `scripts/export_mira.py`

The ruling on #20 kept an epistemic assessment on every claim and rejected both ways it has been
filled: not the analyst's hand-written strength, which nobody has written, and not the paper's
own confidence, which is already on the assertion. It should be derived from the evaluation of
the actual evidence, it needs an operational definition, and it needs a better name. This note
proposes the name, the rule, the layer that computes it, and what happens to the field it
replaces.

## What the format already says, and what it does not do

`docs/claim-format.md` states the principle in its section on conditionality: the epistemic
status of a claim is bounded by the weakest claim it requires, "not by annotation, but by graph
traversal", and a reproduction that fails moves a claim to `contested`. Nothing computes either.
The field is typed by hand at extraction, which is why it carries the role name on 77 claims, an
undefined value on 44, and `contested` on none, including the one claim whose reproduction record
says `mismatch`.

Three things the field has been asked to hold now live elsewhere. The paper's confidence in a
result is `confidence` on the assertion, set by the readers from the paper's verbs. Whether the
paper asserts a claim or raises it to reject is `stance`. Whether a number reproduced is the
reproduction record. What is left is the thing the ruling asks for: given all of that, how well
is the claim supported.

## The name

`warrant`. It is what the tree gives a reader grounds to believe, as distinct from what the
paper says (`confidence`) and from how many readers agreed (`READER_CONFIDENCE` in the contract).
`vocabulary.py` already uses the word for the examples of claims that warrant others.

## The inputs, as they stand

Everything the rule needs is in the claim files today.

| Input | Where | Coverage now |
|:--|:--|:--|
| Test outcomes | `tests` with `confirms` or `refutes` on a prediction (#28) | 39 predictions tested; outcomes on 34 after the #28 re-run of Gädeke, more as papers re-run |
| Controls | incoming `validates` | 34 claims |
| Alternatives | `rules-out` to a claim with stance `rejects` | 12 alternatives |
| Reproduction | `reproductions[].status` | 226 records: verified 60, partial 19, mismatch 1, unverified 38, unattempted 53, blocked 55 |
| Dependencies | outgoing `requires` and `part-of` | 0 `requires` to scope or assumption claims today, which is itself a finding for the readers |
| Cross-paper support | `assertions` from other papers | none yet; every claim has exactly one assertion |

## The rule, version 1

The rule is deliberately coarse, because a fine rule with no adjudicated readings behind it is a
guess with more digits. Four levels, one of them a flag: `strong`, `moderate`, `weak`,
`contested`. The rule is by role, and every value it writes carries the inputs that produced it.

**A prediction** has an outcome, not a warrant: `confirmed`, `refuted`, `untested`, from #28.
The field is still written, so a reader sees one word per claim, and the site shows it as an
outcome.

**An empirical, control, methodological or scope claim** starts from the paper's own assertion
and moves on evidence:

- `contested` if any reproduction is `mismatch`, or if a result in another paper `refutes` it.
- `strong` if a reproduction is `verified`, or if at least one control `validates` it and no
  reproduction is `partial`.
- `weak` if its only reproduction is `partial`, or if the assertion's own confidence is `weak`
  or `tentative` and nothing checks it.
- `moderate` otherwise: asserted, with checks `unattempted`, `blocked` or `unverified`.

**A hypothesis** is warranted by its predictions and its rivals:

- `contested` if any of its predictions is `refuted`.
- `strong` if at least one prediction is `confirmed`, none refuted, and every alternative that
  `addresses` the same question is ruled out.
- `moderate` if at least one prediction is `confirmed` and an alternative stands.
- `weak` if no prediction has an outcome.

**An alternative** (a hypothesis with stance `rejects` or `entertains`) is `ruled-out` when a
`rules-out` edge reaches it, else `open`. This is where the ruling's other point lands: the six
Gädeke alternatives all read `weak` today, which says nothing about whether each was a live
rival or a long shot. `ruled-out` with the ruling-out claim named says what the paper did.

**Propagation**, from the format's own rule: a claim's warrant is bounded above by the weakest
claim it `requires`, computed by traversal. With zero such edges today this changes nothing and
costs nothing, and it starts working the first time a reader writes a `requires` to a scope claim.

**A synthesis or interpretation** claim takes the minimum over the claims it `interprets`.

## The layer

`warrant` is a feature layer, paper scope, mechanical, with no model call: it reads the tree,
the reproduction records and the verification provenance, and writes `warrant:` and
`warrant_from:` into each claim file, the second being the list of inputs the rule used. It
needs `claim-tree`, `stance`, `prediction-outcome` and `verification`, so it runs last and goes
stale whenever any of them moves, which is the behaviour the format asked for by hand and never
got. It is approvable like any layer, and an adjudication verdict may override a value with a
reason; the override is a verdict, carried like the others, and the badge counts it.

## What happens to `epistemic`

It is removed from the format, the schema page and the readers' output. The claim-tree writer
stops emitting it. `export_mira.py` maps `warrant` where it mapped `epistemic` and drops
`haakx:epistemicStatus`. The 353 current values are dropped, not migrated: none of them was the
thing the field was for, and the first run of the layer replaces them all.

## How the rule is evaluated

The rule is a scheme, and it is scored the way the procedure note says a scheme is: against a
reading. The Gädeke v3 adjudication produces the adjudicator's own view of what each claim
rests on, and agreement between that and the rule's output is the first measurement. The second
is a single fact: the one `mismatch` in the corpus must come out `contested`, and today nothing
does.

## Cost

The rule and the layer, with tests: one day. Format, schema page, writer and exporter: half a
day. The first run on ten papers: minutes, since nothing is modelled.

## What this does not decide

The thresholds, which the first reading will move. Whether cross-paper assertions, when they
exist, raise a warrant or only count. Whether `warrant` should also be shown as a number rather
than a level; the inputs are recorded, so a number can be derived later without re-running.
