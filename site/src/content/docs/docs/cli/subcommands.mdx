The CLI exposes seven subcommands. Five of them induce a claim tree and check it: `extract` produces a draft, `write` consumes a draft and produces claim files, `verify-refs` operates on claim files, `run` chains those three for unattended use, and `evaluate` scores the result against a curated reference. The remaining two ask the opposite question — not *is this claim right* but *what in the paper does no claim account for*: `coverage` reports it, and `mark` writes the answer back into the document.

The tables below list every option each subcommand accepts. Where a table says "shared", the option comes from one of the two groups at the [bottom of this page](#options-shared-across-subcommands).

<Aside type="note">
Run the CLI as `python3 -m elife_extract.cli <subcommand>` from `extract/`, or as `elife-extract <subcommand>` if you installed the package. Both are the same entry point; the examples below use the short form.
</Aside>

## `extract` — steps 1-4

```bash
elife-extract extract \
  --doi 10.7554/eLife.95562 \
  --corpus-dir ./claims \
  --output-dir ./out
```

**Reads:** the paper. eLife DOIs fetch JATS XML (cached under `~/.cache/elife-extract/`); `--pdf-path` takes a local PDF instead. Also reads the prompt files for the active variant.

**Writes:** `draft-<slug>.json` and `agents-<slug>.json` into `--output-dir`. **No claim files.** The two-phase shape is deliberate — the methodology's Step 5 review gate says nothing reaches the corpus until the draft is approved.

| Flag | Meaning | Default |
|:-----|:--------|:--------|
| `--doi` | Paper DOI. Optional when `--pdf-path` is given, but at least one of the two is required. | — |
| `--pdf-path` | Local PDF; bypasses the eLife fetch. | — |
| `--input-format` | `auto` / `jats` / `pdf`. `auto` means JATS for eLife DOIs, PDF otherwise. | `auto` |
| `--paper-slug` | Override the slug derived from the paper's title. | derived |
| `--max-claims` | Hard cap on per-paper claim count (cost control for batches). | unlimited |
| `--no-retry-on-thin` | Don't retry an agent whose output looks thin. | retry enabled |
| `--reconcile-strategy` | `confidence-tagged` / `union` / `intersection-only` / `majority-vote` | `confidence-tagged` |
| `--output-dir` | Where the draft and agent JSON land. | `ELIFE_EXTRACT_OUTPUT`, else `./out` |
| (shared) | corpus, prompt, model and backend options | — |

<Aside type="caution" title="The derived slug is not the corpus slug">
`prepare` derives a slug from the paper's title, so Gädeke 2026 comes out as `gadeke-2026-contributions-insula-superior`, not the `gadeke-2026-guilt-insula` this corpus uses. Pass `--paper-slug` whenever you are working against an existing claim tree, or the paths will not line up.
</Aside>

Cost: ~$4-5. Time: ~5 min.

## `write` — steps 5-7

```bash
elife-extract write \
  --draft ./out/draft-<slug>.json \
  --corpus-dir ./claims \
  --review-mode interactive
```

**Reads:** the draft JSON. In `--review-mode external` it also re-fetches the paper, because the reviewer needs the source text, not just the draft.

**Writes:** per-claim `.md` files plus an `index.md` into `<corpus-dir>/<slug>/`. Under `--format oxa` it writes one OXA JSON Document for the paper instead. External review additionally saves `draft-<slug>.reviewed.json` next to the input draft, so the revision is auditable rather than silent.

| Flag | Meaning | Default |
|:-----|:--------|:--------|
| `--draft` (required) | Path to the draft JSON from `extract`. | — |
| `--format` | `yaml` (one markdown file per claim) or `oxa` (single OXA Document). | `yaml` |
| `--review-mode` | `interactive` / `auto-approve` / `external` / `dry-run` | `interactive` |
| `--edges-json` | Answer Step 6 from this file instead of calling a backend. Validated identically to an inferred answer. | — |
| `--dump-edge-prompt PATH` | Write the exact Step 6 prompt to `PATH` and exit. | — |
| (shared) | corpus, prompt, model and backend options | — |

The four review modes have very different cost/quality profiles. See [review modes — when to use each](/elife-claim-trees/docs/cli/review-modes/) for the decision tree.

`--dump-edge-prompt` and `--edges-json` are a pair. The first hands you the question the pipeline would have asked; the second takes the answer back. This is how the dependency step gets answered by something other than the configured provider — an analyst, or a reasoning agent — without anyone paraphrasing the question from memory.

Cost: $0 (`auto-approve`, `dry-run`, `interactive`) or ~$2 (`external`). Time: &lt;1s to ~5 min depending on mode.

## `verify-refs` — CrossRef DOI resolution

```bash
elife-extract verify-refs --paper <slug> --corpus-dir ./claims
```

**Reads:** every `role: literature-context` claim under `<corpus-dir>/<slug>/`, or the whole corpus if `--paper` is omitted. Queries CrossRef.

**Writes:** the resolved DOI back into each claim's top-level `doi:` frontmatter, unless `--dry-run`.

Two paths per claim. **Confirm:** the claim already carries a DOI, and CrossRef is asked whether it resolves to a real paper — an anti-hallucination check. **Found:** no DOI yet, so Author (Year) hints are pulled from the claim text and slug, CrossRef is queried, and the highest-scoring match above threshold is written back.

| Flag | Meaning | Default |
|:-----|:--------|:--------|
| `--paper` | Single paper slug. Omit to sweep the entire corpus. | sweep all |
| `--dry-run` | Print resolutions without writing back. | writes |
| (shared) | corpus, prompt and backend options | — |

Cost: $0. Time: ~1s per cited paper.

## `run` — composed shorthand

```bash
elife-extract run --doi 10.7554/eLife.95562 --corpus-dir ./claims
```

Chains `extract` → `write --review-mode auto-approve` → `verify-refs` in one process, passing the draft path and slug forward. For tests, demos, and unattended batches where curator-quality output is not the goal.

**Note:** `run` bypasses the review gate. For bulk work that keeps the Opus reviewer, call `extract` and `write --review-mode external` separately, or use `evaluate`.

| Flag | Meaning | Default |
|:-----|:--------|:--------|
| `--doi` / `--pdf-path` | As for `extract`; one is required. | — |
| `--input-format` | `auto` / `jats` / `pdf` | `auto` |
| `--paper-slug` | Override slug. | derived |
| `--max-claims` | Hard cap on claims. | unlimited |
| `--reconcile-strategy` | As for `extract`. | `confidence-tagged` |
| `--output-dir` | Where the draft and agent JSON land. | `ELIFE_EXTRACT_OUTPUT`, else `./out` |
| (shared) | corpus, prompt, model and backend options | — |

Cost: ~$5. Time: ~5-7 min.

## `coverage` — what does no claim account for?

```bash
elife-extract coverage \
  --doi 10.7554/eLife.105391 \
  --paper-slug gadeke-2026-guilt-insula \
  --claims-dir ./claims/gadeke-2026-guilt-insula \
  --mapping ./mappings/gadeke-2026-guilt-insula.json
```

**Reads:** the paper, the claim tree named by `--claims-dir`, and optionally a mapping file of adjudicated verdicts.

**Writes:** a report to stdout, and the full report as JSON if `--json` is given. It never touches the corpus.

**Makes no model calls,** so it is free, fast, and usable as a gate on every paper in the corpus.

This asks a different question from `evaluate`. `evaluate` scores agreement between two claim sets, which says nothing about what both of them missed — you can score 100% agreement on a third of a paper. `coverage` takes its denominator from the paper: it inventories the panels and statistics, segments the whole text into sentences, and reports which sentences carry a result that no claim states.

| Flag | Meaning | Default |
|:-----|:--------|:--------|
| `--claims-dir` (required) | The claim tree to measure against. | — |
| `--doi` / `--pdf-path` | The paper; one is required. | — |
| `--input-format` | `auto` / `jats` / `pdf` | `auto` |
| `--paper-slug` | Override slug. | derived |
| `--include-methods` | Count methods sentences as obligations too. Off by default: the corpus claims results, not procedure. | off |
| `--mapping` | Adjudicated verdicts for spans the mechanical match could not resolve. | — |
| `--json PATH` | Also write the full report as JSON. | — |
| `--fail-on-orphans` | Exit non-zero if any panel or result is unaccounted for. | off |

Note that `coverage` takes neither the shared corpus options nor any model options — it names its claim tree directly with `--claims-dir` and calls no backend.

The mapping file and the three verdicts it carries are covered in [coverage and marks](/elife-claim-trees/docs/cli/coverage-and-marks/).

Cost: $0. Time: seconds.

## `mark` — write the assignments into the paper

```bash
elife-extract mark \
  --doi 10.7554/eLife.105391 \
  --paper-slug gadeke-2026-guilt-insula \
  --claims-dir ./claims/gadeke-2026-guilt-insula \
  --mapping ./mappings/gadeke-2026-guilt-insula.json \
  -o ./marked/gadeke-2026-guilt-insula.marked.md
```

**Reads:** the same three inputs as `coverage` — paper, claim tree, optional mapping.

**Writes:** a marked-up copy of the paper (default `<slug>.marked.md`), then reads its own marks straight back and fails if they do not reproduce the assignments they were written from.

Where `coverage` gives you a count, `mark` gives you the document. Every span carrying a result gets a tika v2 note naming what became of it: a claim's UUID, `no-assertion`, or `gap`. A sentence with no mark carries no result and was never an obligation — so a hole in the coverage is something you can see by reading the paper rather than only count in a report.

| Flag | Meaning | Default |
|:-----|:--------|:--------|
| `--doi` (required) | The paper. `mark` has no `--pdf-path`. | — |
| `--claims-dir` (required) | The claim tree whose assignments are written. | — |
| `--paper-slug` | Override slug. | derived |
| `--mapping` | Adjudicated verdicts, as for `coverage`. | — |
| `--include-methods` | Mark methods sentences too. | off |
| `--author` | Mark author, recorded in every note. | `zach` |
| `-o`, `--out` | Output path. | `<slug>.marked.md` |

Cost: $0. Time: seconds.

## `evaluate` — round-trip scoring

```bash
elife-extract evaluate \
  --reference-dir ./claims \
  --work-dir ./eval \
  --paper headley-2026-inhibitory-rhythms \
  --review-mode external
```

**Reads:** the curated reference corpus, and the papers behind it.

**Writes:** per-paper extraction artifacts and a `scorecard.json` under `--work-dir`, plus an aggregate scorecard across all papers evaluated.

For each named paper it runs the full pipeline, scores the output against the reference (claim recovery, panel agreement, role agreement, match quality), and aggregates. Use it to validate a prompt iteration or a model substitution empirically before deploying it.

| Flag | Meaning | Default |
|:-----|:--------|:--------|
| `--reference-dir` (required) | The curated reference corpus. | — |
| `--work-dir` (required) | Where artifacts and scorecards land. | — |
| `--paper` / `--papers` / `--all` | One slug, a comma-separated list, or every paper directory. Mutually exclusive. | — |
| `--review-mode` | `auto-approve` / `external` | `external` |
| `--skip-existing` | Skip papers that already have a `scorecard.json`. | re-runs |
| `--prompts-dir`, `--prompt-variant` | Prompt selection. | package prompts, `default` |
| (shared) | model and backend options | — |

Cost: ~$10 per paper. Time: ~15-20 min per paper, sequential.

## Options shared across subcommands

### Corpus and prompts

Accepted by `extract`, `write`, `verify-refs` and `run`.

| Flag | Meaning | Default |
|:-----|:--------|:--------|
| `--corpus-dir` (required) | Where claim files are read and written. | env `ELIFE_CORPUS_DIR` |
| `--prompts-dir` | Override the prompts directory. | package-local `prompts/` |
| `--prompt-variant` | Named variant under `prompts/<variant>/`. | `default` |
| `-v`, `--verbose` | Per-chunk DEBUG logging. | INFO |
| `--no-infer-edges` | Skip Step 6 dependency mapping; claims are written with no edges. | infer |

### Models and backend

`--backend` and `--api-key` are accepted by `extract`, `write`, `verify-refs`, `run` and `evaluate`; the model flags by all of those except `verify-refs`.

| Flag | Meaning | Default |
|:-----|:--------|:--------|
| `--backend` | `vertex`, `anthropic`, or any litellm provider: `openrouter`, `openai`, `google`, `groq`, `together`, `deepseek`. | `vertex` (env `ELIFE_EXTRACT_BACKEND`) |
| `--api-key` | Key for that backend. Not needed for `vertex`. | that backend's env var |
| `--model-results` | Results-reader model. | `claude-sonnet-4-6` |
| `--model-caption` | Caption-reader model. | `claude-sonnet-4-6` |
| `--model-structure` | Structure-reader model. | `claude-sonnet-4-6` |
| `--model-reconcile` | Reconciliation, external review and edge inference. | `claude-opus-4-6` |
| `--vertex-project` | Vertex AI project. | env `VERTEX_PROJECT_ID`, else `cr-mainen` |
| `--vertex-region` | Vertex AI region. | env `VERTEX_REGION`, else `europe-west1` |

Every one of these can also be set by environment variable; the [configuration reference](/elife-claim-trees/docs/reference/config/) lists the full precedence chain.

## Subcommand composition

| Operation | Command sequence |
|:----------|:-----------------|
| Curated single-paper extraction | `extract` → analyst review → `write --review-mode interactive` → `verify-refs` |
| Bulk batch with Opus review | per paper: `extract` → `write --review-mode external` → `verify-refs` |
| Test/demo run | `run --doi <DOI>` |
| Audit an existing tree against its paper | `coverage --claims-dir …` → adjudicate → `coverage --mapping …` → `mark` |
| Gate a corpus in CI | `coverage --fail-on-orphans` per paper |
| Validate a prompt change | `evaluate --all`, compared to a baseline scorecard |
| Inspect without writing | `extract` → `write --review-mode dry-run` |

The full sequence, from a PDF through to the interchange exports, is walked through in [the first paper](/elife-claim-trees/docs/cli/first-paper/).
