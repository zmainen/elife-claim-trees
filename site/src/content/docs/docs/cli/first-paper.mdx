This page is the operational counterpart to [the quick demo](/elife-claim-trees/docs/overview/quick-demo/). The demo explains what is happening conceptually; this page is the commands you type and the output you see. It runs one paper the whole way: from a DOI to a claim tree, then to an audit of what the tree missed, then to the three interchange formats.

The paper is **Gädeke et al. 2026**, *Contributions of insula and superior temporal sulcus to interpersonal guilt and responsibility in social decisions* (DOI `10.7554/eLife.105391`). It is the worked example throughout the repository: its claim tree, its adjudicated coverage mapping, its marked document and its exports are all committed, so every number on this page can be reproduced from a clean checkout.

<Aside type="note">
Commands are shown as `elife-extract …`. If you have not installed the package, run them from `extract/` as `python3 -m elife_extract.cli …` — the same entry point. See [install and configure](/elife-claim-trees/docs/cli/install/).
</Aside>

## Step 0 — Directories

```bash
mkdir -p /tmp/my-corpus/{out,claims}
cd /tmp/my-corpus
```

`out/` holds the JSON intermediates — the reconciled draft, the reviewer-revised draft, the raw per-agent output. `claims/` is the corpus root where claim files land.

## Step 1 — Extract

```bash
elife-extract extract \
  --doi 10.7554/eLife.105391 \
  --paper-slug gadeke-2026-guilt-insula \
  --corpus-dir ./claims \
  --output-dir ./out
```

Steps 1-4 of the methodology: fetch, slice, three Sonnet extractions, Opus reconciliation. **No claim files are written yet.**

The preparation step reports what it found:

```
=== Step 1 — Prepare ===
  doi    = 10.7554/eLife.105391
  slug   = gadeke-2026-guilt-insula
  title  = Contributions of insula and superior temporal sulcus to interpersonal
           guilt and responsibility in social decisions
  path   = jats
  slices = abstract:1931c results:33886c captions:8496c methods:32690c
  panels = 40 detected
```

Two things in that block are worth pausing on.

`path = jats` means the paper came in as structured XML rather than as a PDF. For eLife DOIs this is the default and it matters: JATS gives clean section boundaries and caption text, where a PDF gives a column-order guess. The fetched XML is cached under `~/.cache/elife-extract/`, so re-running any command on the same paper is free and offline. Pass `--input-format pdf`, or `--pdf-path` with a local file, for papers that are not eLife.

`slug = gadeke-2026-guilt-insula` is there because we asked for it. Without `--paper-slug`, the slug is derived from the title and comes out `gadeke-2026-contributions-insula-superior`, which is a perfectly good slug and not the one this corpus uses. Whenever you are working against an existing claim tree, name the slug.

The three agents then run in parallel and the reconciler merges them, tagging each surviving claim `high`, `contested` or `single-source`. The draft lands in `out/`:

```
=== Output ===
  draft  → ./out/draft-gadeke-2026-guilt-insula.json
  agents → ./out/agents-gadeke-2026-guilt-insula.json
  Next: elife-extract write --draft ./out/draft-gadeke-2026-guilt-insula.json --corpus-dir ./claims
```

`draft-*.json` is the reconciled table — each claim with its confidence, its sources and the per-agent evidence quotes. `agents-*.json` is the raw per-agent output, preserved for audit rather than for reading.

Wall time: ~5 minutes. API cost: ~$4-5.

## Step 2 — Write

```bash
elife-extract write \
  --draft ./out/draft-gadeke-2026-guilt-insula.json \
  --corpus-dir ./claims \
  --review-mode external
```

This runs the Step 4.5 external reviewer, then Steps 5-7: the review gate, dependency mapping, and the write itself. `--review-mode external` re-fetches the paper — the reviewer reads the source, not just the draft — calls Opus, and saves the revision as `draft-gadeke-2026-guilt-insula.reviewed.json` beside the original, so what the reviewer changed stays inspectable.

Claim files land one per claim in `./claims/gadeke-2026-guilt-insula/`, alongside an `index.md`. The committed tree for this paper holds **33 claims and 93 typed relations between them**; a fresh run will land near that but not on it, since the extraction is three model calls and a fourth reconciling them.

<Aside type="caution" title="No human checks this">
`--review-mode external` substitutes a model for the human review the methodology specifies. It is not a human review, and nothing downstream marks the difference. See [review modes](/elife-claim-trees/docs/cli/review-modes/) for what each mode does and does not give you.
</Aside>

Open a claim to see the schema:

```bash
head -20 ./claims/gadeke-2026-guilt-insula/lottery-choice-increases-with-ev.md
```

```yaml
---
uuid: 49d08c4f-7b31-4967-9ab7-06aa50a006b4
slug: lottery-choice-increases-with-ev
doi: ~
claim: >
  Probability of lottery selection increases with expected value advantage in
  both Study 1 (t(4796)=9.26, p<3.1e-20, β=0.074) and Study 2 (t(3829)=10.62,
  p<5.3e-26, β=0.093), confirming participants were sensitive to expected value
  in their choices.
claim-type: empirical
role: control
concepts:
  - lottery choice
  - expected value
priority: 2026-03-30
epistemic: strong

rules-out:
  - alt-participants-insensitive-to-value
validates:
  - responsibility-modulates-guilt-computational
  - hypothesis-insula-tracks-interpersonal-guilt
---
```

`role: control` rather than `empirical`: this is the manipulation check, and the tree records what a claim *does* in the paper's argument separately from what kind of thing it is. The relations below the blank line are the edges — this one rules out an alternative explanation and validates two claims that depend on it.

The `uuid` is the claim's durable identity. The slug is derived from the claim's text, so rewording the claim changes it; the UUID does not. Everything downstream — the MIRA nodes, the marks written into the paper — keys on the UUID for exactly that reason.

Wall time: ~5 minutes. API cost: ~$2.

## Step 3 — Verify references

```bash
elife-extract verify-refs \
  --paper gadeke-2026-guilt-insula \
  --corpus-dir ./claims \
  --dry-run
```

For each `role: literature-context` claim, CrossRef is asked to resolve the cited paper. A claim that already carries a DOI is *confirmed* — an anti-hallucination check that the DOI names a real paper. A claim without one has Author (Year) hints pulled from its text and slug, and the highest-scoring match above threshold is written back to frontmatter.

`--dry-run` shows the resolutions without writing. Drop it to commit them.

Cost: $0. Wall time: ~1s per cited paper.

At this point you have a claim tree. The next three steps ask whether it is any good.

## Step 4 — Coverage: what did the tree miss?

```bash
elife-extract coverage \
  --doi 10.7554/eLife.105391 \
  --paper-slug gadeke-2026-guilt-insula \
  --claims-dir ./claims/gadeke-2026-guilt-insula
```

No model calls, so this is free and fast. It takes its denominator from the paper rather than from the claim set — inventorying panels and statistics, then segmenting the whole text into sentences and asking which of them carry a result that no claim states.

```
Coverage — gadeke-2026-guilt-insula
  panels     20/40  (50%)
  statistics 46/90  (51%)

  UNCLAIMED PANELS (20):
    fig1, fig2c, fig2f, fig3s1, fig4c, fig4d, fig4i, fig5s1, keyresource,
    app1table1, app1table2, … app1table11

  CITED AT FIGURE LEVEL, NOT PANEL (2):
    fig3, fig4

Span coverage — gadeke-2026-guilt-insula
  245 spans segmented from the paper (abstract=12, results=153, captions=47, tables=33)
  93 carry a statistic or name a panel; 152 are prose that asserts no result
  accounted for by a claim: 57/93 (61%)

  NOT ACCOUNTED FOR (36) — each carries a result that no claim states:
    [results-007] There was no significant interaction between the difference in
           expected values and experimental conditions in either study
    …
```

Read those numbers carefully, because the mechanical match is a proxy and wrong in both directions. It asks "does some claim restate this statistic or name this panel", which misses a claim that states an effect without repeating its numbers, and counts a bare panel label in a caption as an obligation nobody has met. Half the unclaimed panels above are appendix tables.

So the residue is judged once, by hand, and the judgement is stored.

## Step 5 — Adjudicate the residue

The verdicts live in `mappings/<slug>.json`. Each entry resolves one span the matcher could not:

```json
{
  "paper": "gadeke-2026-guilt-insula",
  "adjudicated": "2026-09-09",
  "spans": [
    {
      "uid": "results-007",
      "verdict": "gap",
      "claim": null,
      "why": "No claim states the null interaction between expected-value difference and condition; the EV claim covers only the main effect.",
      "sha": "5215ac14"
    },
    {
      "uid": "results-063",
      "verdict": "covered",
      "claim": "responsibility-modulates-guilt-computational",
      "why": "The claim asserts the Responsibility model outfits models without responsibility weighting, which is exactly this R-squared comparison.",
      "sha": "7873ef79"
    }
  ]
}
```

Three verdicts are available. **`covered`** — a claim does account for it and the matcher could not see that. **`gap`** — nothing in the tree accounts for it; a real hole. **`not-an-assertion`** — the span states no result of its own: a cross-reference, analysis narration, a bare panel label.

Keeping the third apart from the second is the whole point. Nine of Gädeke's unmatched Results spans assert nothing, and reporting them as unmet obligations buried the ten that matter.

Each verdict carries `sha`, the fingerprint of the sentence it was judged about. Span ids are positional, so inserting one sentence earlier in a section shifts every id after it. If the fingerprint no longer matches, the verdict is **discarded** and the span goes back to being unexamined — recoverable, where applying it would be a wrong judgement wearing the authority of a human decision.

## Step 6 — Coverage, with the verdicts folded in

```bash
elife-extract coverage \
  --doi 10.7554/eLife.105391 \
  --paper-slug gadeke-2026-guilt-insula \
  --claims-dir ./claims/gadeke-2026-guilt-insula \
  --mapping ./mappings/gadeke-2026-guilt-insula.json \
  --json ./out/coverage-gadeke.json
```

```
Span coverage — gadeke-2026-guilt-insula
  245 spans segmented from the paper (abstract=12, results=153, captions=47, tables=33)
  78 carry a statistic or name a panel; 152 are prose that asserts no result
  accounted for by a claim: 64/78 (82%)
  adjudicated as asserting no result: 15 (cross-references, analysis narration, bare panel labels)

  GAPS (14) — each carries a result that no claim states:
    [results-007] There was no significant interaction between the difference in
           expected values and experimental conditions in either study
           stats: p > 0.52
    [results-026] We found that participants were slightly more risk averse in the
           Social than in the Solo condition in Study 1
           stats: t (39) = 2.27, p = 0.03, d = 0.36, BF 10 = 1.69
    …
```

That is the real figure: 245 spans, 78 carrying a result, 64 accounted for, 15 asserting nothing, **14 real gaps, nothing unexamined**. The 36 unmatched spans of Step 4 resolve into 22 the matcher was wrong about and 14 it was right about; the denominator drops from 93 to 78 because the 15 spans that assert nothing were never obligations. Add `--fail-on-orphans` to turn the same command into a CI gate.

## Step 7 — Write the assignments into the paper

```bash
elife-extract mark \
  --doi 10.7554/eLife.105391 \
  --paper-slug gadeke-2026-guilt-insula \
  --claims-dir ./claims/gadeke-2026-guilt-insula \
  --mapping ./mappings/gadeke-2026-guilt-insula.json \
  -o ./marked/gadeke-2026-guilt-insula.marked.md
```

```
=== Marked — gadeke-2026-guilt-insula ===
  assigned to a claim : 64
  states no result    : 15
  unclaimed (gap)     : 14
  unmarked prose      : (carries no result — never an obligation)
  written             : ./marked/gadeke-2026-guilt-insula.marked.md
  round-trip          : OK — 93 marks read back identically
```

A count in a report is something you audit; a marked document is something you read. Every span carrying a result now has a note anchored to it naming what became of it, and the last line is the check that matters — the marks are parsed straight back out of the document just written, and the command fails if they do not reproduce the assignments they came from.

See [coverage and marks](/elife-claim-trees/docs/cli/coverage-and-marks/) for the mark grammar and why an assignment is anchored to a quote rather than to a line number.

## Step 8 — Export

Three interchange formats, all generated from the claim tree, none of them requiring a model:

```bash
# MIRA JSON-LD: strict core, an extended file, and a gap report per paper
python3 scripts/export_mira.py gadeke-2026-guilt-insula

# OXA: one JSON Document for the paper, with a ClaimGraph
cd extract && python3 scripts/migrate_to_oxa.py \
    ../claims/gadeke-2026-guilt-insula --output-dir ../exports

# Discourse Graphs JSON-LD, converted from the OXA document
python3 scripts/export_discourse_graphs.py \
    ../exports/gadeke-2026-guilt-insula.oxa.json \
    --output ../exports/gadeke-2026-guilt-insula.dg.jsonld

# and the comparison between them, measured from those files
cd .. && python3 scripts/formats_report.py gadeke-2026-guilt-insula
```

```
  gadeke-2026-guilt-insula   93 relations · MIRA loses 0 ( 5 inverse-only) · OXA 93 · DG 93
```

The exports are byte-stable: regenerate them on an unchanged corpus and `git diff` is empty. That makes the diff a real check rather than a formality — if the corpus changed and an export did not, or the other way round, the diff says so.

Run the exporters in that order. The Discourse Graphs export reads the OXA document rather than the claim files, so an OXA export left stale silently makes the DG export stale too, and the formats report will then measure both against the wrong thing.

What you end up with, in `exports/`:

| File | What it is |
|:-----|:-----------|
| `<slug>.mira.jsonld` | Strict MIRA core — what eLife's platform reads |
| `<slug>.mira-extended.jsonld` | The same graph plus what MIRA has no vocabulary for |
| `<slug>.gap-report.md` | Exactly what the strict file could not carry |
| `<slug>.oxa.json` | The paper as one OXA Document with a ClaimGraph |
| `<slug>.dg.jsonld` | Discourse Graphs JSON-LD |
| `<slug>.formats.md` / `.json` | The comparison, as prose and as numbers |

The formats report is the artifact the site's [formats page](/elife-claim-trees/formats/) renders, rather than restating — a figure on the site cannot then disagree with the export it describes.

## All in one shot

For unattended runs, the first three steps compose:

```bash
elife-extract run \
  --doi 10.7554/eLife.105391 \
  --paper-slug gadeke-2026-guilt-insula \
  --corpus-dir ./claims
```

`run` chains `extract` + `write --review-mode auto-approve` + `verify-refs`. It bypasses the review gate entirely — no human, and no external reviewer either. Use it for tests and demos; for bulk work that keeps the reviewer, run `extract` and `write --review-mode external` separately.

## Total cost and time

| Step | Wall time | API cost |
|:-----|:----------|:---------|
| `extract` — fetch + 3 Sonnet + Opus reconcile | ~5 min | ~$4-5 |
| `write --review-mode external` | ~5 min | ~$2 |
| `verify-refs` — CrossRef | ~1s per cited paper | $0 |
| `coverage`, `mark` — no model calls | seconds | $0 |
| the four exporters | seconds | $0 |
| **Total** | **~10-15 min** | **~$6-7** |

Everything after `verify-refs` is free and offline once the paper is cached, which is what makes the coverage audit worth running on every paper rather than on the ones you are worried about.
